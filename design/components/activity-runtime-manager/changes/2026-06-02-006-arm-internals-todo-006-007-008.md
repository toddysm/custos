## Summary

Filled every remaining **(pending)** section of the Activity Runtime Manager
design, closing the three open structural TODOs that gate implementation:

- **TODO-006** — sandbox technology decision (REQ-039 / requirements TODO-002).
- **TODO-007** — the Runtime Driver dispatcher contract.
- **TODO-008** — the sub-module deep dive.

The locked contracts from earlier iterations (Activity Contract v1 file layout,
platform types, Activity Manifest v1, Error Envelope & Exit Codes, the
`ScheduleActivity` / `CancelActivity` surface) are unchanged; this iteration only
adds the internal realization that sits behind them. Version 5 → 6.

## After

### Internal Structure (TODO-008 + TODO-007)

- Added the nine-sub-module breakdown matching `components.md` COMP-006
  (RPC Adapter, Activity Scheduler, Activity Resolver, Resource Limiter,
  I/O Broker, Secret Injector, Runtime Driver Dispatcher, OCI Container Driver,
  Artifact Store Client, Log Streamer, Result Mapper, Execution Store) with a
  responsibility/collaborator table and a `graph TD` structure diagram.
- **TODO-007**: specified the `RuntimeDriver` Protocol
  (`prepare` / `start` / `await_terminal` / `cancel` / `collect` / `cleanup`)
  selected by `manifest.spec.runtime.kind`. v1 registers only the OCI Container
  Driver; HTTP (M3) and WASM (M4+) are future drivers behind the same contract.
  Cross-cutting concerns (I/O, secrets, artifacts, result mapping) live **above**
  the dispatcher so drivers stay thin and contract semantics stay identical
  across runtimes.

### Sandbox and Isolation Model (TODO-006)

- The abstract tier ladder (`process` / `vm` / `microvm`, already locked on the
  manifest) maps to **operator-configured** Kubernetes `RuntimeClass` objects via
  Helm (`ARM_RUNTIME_CLASS_PROCESS|VM|MICROVM`), not hard-coded names.
- **M1 guarantees the `process` tier only** (runc + a hardened baseline
  `SecurityContext`: non-root, read-only rootfs, all caps dropped, seccomp
  `RuntimeDefault`, tmpfs-only writable mounts, no host namespaces). `vm`
  (Kata-CLH/MSHV) and `microvm` (Kata-Firecracker) are operator opt-in.
- **gVisor is intentionally omitted** from the v1 ladder; only runc and Kata are
  named.
- **No silent downgrade**: when a manifest's `isolation.minTier` exceeds the
  highest tier the cluster has a `RuntimeClass` for, ARM hard-fails the attempt
  with `system.runtime_unavailable` (class `permanent`) before any sandbox is
  created. Workflows may upgrade a step's tier but never downgrade below the
  manifest floor.

### Key Operations

- Execute-activity happy path (sequence diagram), cancel/timeout, failure
  classification (deferring to the locked Error Envelope rules), idempotent
  replay on the `(runId, stepId, attempt)` triple, and downstream `ArtifactRef`
  materialization.

### Data Models

- `ActivityExecution` (idempotency record keyed by the triple, with a documented
  state machine) and `ArtifactRecord`, both via the SPL abstractions, with an ER
  diagram.

### Public Interface

- Promoted from partial to complete: the inbound `ScheduleActivity` /
  `CancelActivity` Dapr Service-Invocation surface (with the `Idempotency-Key`
  header and 404/409 cancel semantics), the result envelope, and the outbound
  RPC set (Catalog, Connector `RefreshLease`, SPL, Observability).

### Configuration

- Added the `ARM_*` environment variable table (store bindings, service
  endpoints, sandbox namespace, tier→`RuntimeClass` mapping, platform-default
  resources, timeout ceiling, output/artifact size caps, idempotency TTL,
  sidecar image, dev-shim/env knobs).

### Failure Modes

- Added a failure → detection → behavior → error-code/class table covering
  resolution, schema, connector/secret, runtime-unavailable, image pull,
  timeout/cancel, OOM/crash, contract violation, output-size/schema, artifact
  upload, and mid-attempt ARM crash reconciliation.

## Impact

- ARM is now implementation-ready: the `implement-component plan` gate-1 plan can
  be derived against a complete design rather than against `(pending)` sections.
- No change to any locked cross-component contract (`ScheduleActivity` /
  `CancelActivity` shapes, sidecar token minting, two-phase output finalization,
  error namespaces) — Workflow Service, Connector Service, Catalog, and SPL are
  unaffected.
- New operational surface for the platform/Helm chart: the tier→`RuntimeClass`
  mapping and the `ARM_*` configuration variables.
- requirements TODO-002 / issue #4 (sandbox technology) is now answered on the
  ARM side; the requirements ledger can cross-reference this decision.
